Rules in this Prototype

  1. The start date field is empty by default, and is occurrence 1 regardless of the rule.
  2. Checking "Is recurring event" while the start date is empty auto-fills it with today's date.
  3. Clearing the start date after "Is recurring event" is checked shows the "date/time fields are required" error and clears the computed "Ends" end date.
  4. Weekly recurrence always includes the start date's own weekday, and that chip is locked — it can't be deselected — to keep the rule valid. Other weekdays can still be added manually.
  5. Changing the start date only swaps which weekday chip is locked — it doesn't clear any weekday the submitter manually added. If the previous locked day was never manually added on top, it's unchecked automatically once it stops being the start date's weekday.
  6. Monthly recurrence is always derived from the start date: the day-of-month and the nth-weekday pattern are shown as plain text, not editable fields, and update automatically when the start date changes.
  7. Starting on the 30th or 31st shows a warning that short months will repeat on their last day instead of being skipped.
  8. Editing the "Ends" end date recalculates the occurrence count. Editing anything else about the rule — interval, unit, start date, weekday selection, and so on — recalculates the end date instead. The occurrence count is never recalculated by anything other than a direct edit to the end date.
  9. Exceeding the maximum recurrence range will show an error.
  10. With no end date, only the first 5 occurrences are shown and the stored value is the rule.
  11. When "Is recurring event" is unchecked, the recurrence settings are only hidden, not cleared. Checking it again restores the same selections exactly as left — only the weekly lock and monthly text refresh to match the current start date.
  12. When "Is recurring event" is checked, an empty or partially filled-in date/time field will show an error — e.g. no start date entered, a start date with no end date on a range, or a start date with no time where time is expected.

Error Messages

Validation messages caused by "Is recurring event" being checked, and what triggers each one.

Errors

#MessageTrigger
1The date/time fields are required for a recurring event."Is recurring event" is checked, and the date/time fields are empty or incomplete (e.g. a start date but no end date on a range) — including clearing a start date that was already filled in.
2End date exceeds the maximum recurrence range (on or before [date]).Either the "Ends" end date is edited past the builder's "Maximum recurrence range", or the occurrence count would require dates past it.
3Enter an end date for the series."Ends" is set to "On occurrence or end date" and the end date field is cleared.
4End date must be on or after the start date.The "Ends" end date is edited to a date before the start date.
5Occurrences overlap. Shorten the range or repeat less often.A range occurrence's duration runs past the start of the next occurrence.

Warnings

#MessageTrigger
1Short months will repeat on the last day.Monthly recurrence, "On [day] of every month" mode, and the start date is the 30th or 31st.
2With 1 occurrence this event does not repeat."Ends" occurrence count is set to 1.
